# v0.3.0 测试版（2026-09-20）

## 已实现

- 独立学期日历：第一周星期一、总周数、确认时间和来源；总周数不再取课程最大周次。
- 月份放表头左侧，各列显示星期和日期，跨月第一天显示月/日，跨年日期范围包含年份。
- 今天日期高亮、当前周计算、回到本周、学期前/后状态，以及空白周翻页。
- 从 loadPkjg 的 jcfaList[].skjcList[] 读取 DM、KSSJ、JSSJ；关联节次方案 DM/JCFADM。
- 导入时从可见课程明细的首次上课日期与排课周次交叉校验第一周星期一。至少两条结果一致才填建议，仍需用户确认。
- SQLite 保存学期、课程和同步快照，事务更新；v0.2 首次启动迁移且保留原偏好存储备份。
- 同步前变化预览；以教学周/星期/单节次展开去重，课程分段变化不产生假变化。移动/教室/教师变化目前展示为移除旧安排和新增安排。
- 空课表、部分无效排课阻止覆盖。导入超时提示及请求编号防止迟到结果覆盖新的请求。
- 中文日期/时间选择器；用户可确认学期日期、总周数和编辑节次时间。

## 学校实测证据

- 学校前端 xskcb.js 的 getWeekList 固定产生 1—30 周，不表示真实学期长度。
- xskcb.js 将 jcfaList[].skjcList[].KSSJ/JSSJ 格式化为时间，故无需另行猜测时间表。
- 当前课表 13 节起止时间已在登录后的页面核对；第1节 08:15—09:00，第13节 20:45—21:30。
- 9 门可解析的首次上课日期交叉推得 2026-09-14。这个结论是建议日期，不是直接读取的官方校历。
- 日期安排 rqapjgcx.do 的公开前端包装存在，但此轮浏览器直接打开查询返回 ERR_BLOCKED_BY_CLIENT，未取得响应、不能确认字段及学期结束日期。
- 总周数 20 来自用户提供；程序中的新学期默认20明确标为待确认，不自动宣称每学期20周。

## 范围与限制

- 日期安排接口自动识别、完整特殊日期映射仍未完成；日期以用户确认的第一周星期一连续计算。学校已在排课周次中表达的周末补课会正常显示。
- 不识别学校尚未写入课表的调课通知。
- 暂无通知、后台同步或正式发布签名；本包使用与旧版相同的调试签名。
- 同步历史保存于本地数据库，暂未提供历史浏览/恢复界面。
- 多套冲突时间方案不在左侧任取一个，课程详情按自身方案查时间。

## 验证

- 13 项自动测试：含真实 SQLite 迁移、事务回滚、周次和日期边界、手机宽度下跨月显示与翻至20周。
- 独立预览渲染测试，使用虚构课程与本机中文字体；预览不包含用户课程资料。
- 学校登录、日期交叉校验和时间表已在桌面页面验证；新版 APK 的 WebView 导入与数据库迁移仍需手机安装后验证。
