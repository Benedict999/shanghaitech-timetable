# 上海科技大学研究生课表接入调查

调查日期：2026-09-19

## 结论

接入方案可行。研究生综合服务平台通过上海科技大学统一身份认证登录，登录后在同源页面中加载“学生课程表”模块。课表不是图片：它由结构化 JSON 数据渲染，同时页面下方还提供结构化课程明细表。

应用应采用以下方式接入：

1. 使用 Android WebView 打开学校官方入口。
2. 用户只在学校官方身份认证页面中自行登录。
3. WebView 到达研究生综合服务平台后保留临时会话 Cookie。
4. 在同一 WebView 会话中请求课表查询接口。
5. 将响应映射为应用内部模型，立即进行字段校验和标准化。
6. 仅将标准化后的课表保存在本地数据库；密码和 Cookie 不进入业务数据库或日志。

普通无会话 HTTP 请求会收到 `403`，因此不能使用独立后台程序模拟登录，也不能依赖脱离 WebView 会话的直接抓取。

## 已确认入口

- 门户：`https://graduate.shanghaitech.edu.cn/gsapp/sys/yjsemaphome/portal/index.do`
- 统一身份认证域名：`ids.shanghaitech.edu.cn`
- 课表模块：`/gsapp/sys/wdkbappshtech/`

## 已确认排课字段

排课结果脚本使用的核心字段包括：

- `KCMC`：课程名称；
- `BJMC` / `BJDM`：教学班名称与代码；
- `ZCMC`：周次文字；
- `XQ`：星期；
- `KSJCDM` / `JSJCDM`：开始、结束节次；
- `JCFADM`：节次方案；
- `JGJSXM`：该次排课的教师；
- `JASMC`：教室；
- `BYBZ`：本研标志。

课程明细还包含：

- 课程代码、课程名称、班级名称；
- 课程学时、学分；
- 校区、开课单位；
- 上课方式、授课形式；
- 任课教师、上课人数；
- 首次上课日期；
- 上课时间地点；
- 选课备注和课表备注。

## 必须覆盖的复杂情况

解析和测试至少覆盖：

- 连续周次，例如 `1-16周`；
- 多个范围，例如 `1-3,5-16周`；
- 离散周次，例如 `9,14周`；
- 单周次，例如 `4周`；
- 同一课程临时换到星期六或星期日；
- 同一课程在不同周采用不同节次数；
- 同一课程在不同周由不同教师授课；
- 课程已经选中但尚未排出时间、教师或教室；
- 一天晚间第 10 至第 13 节；
- 页面节次方案变化；
- 学校接口返回空数据或登录会话过期。

## 同步策略

每次同步生成不可变的标准化快照，再与本地有效课表比较：

- 新增或删除课程；
- 新增、取消或移动某一次上课；
- 周次、星期、节次、教师、教室变化；
- 节次对应的实际时间变化；
- 课程备注变化。

学校数据与用户本地数据分层保存。用户颜色、提醒、备注等本地设置不能因为学校同步而丢失。同步产生的变化在应用中预览后再合并；首次导入可以直接创建课表。

## 安全要求

- 仅允许导航到上海科技大学受信域名；外部链接交给系统浏览器处理。
- 禁止忽略 TLS/证书错误。
- 登录页面由学校提供，应用不得注入账号密码。
- Cookie 只存放于受系统保护的 WebView Cookie 存储；登出时允许用户清除。
- 网络日志不得记录 Cookie、认证头、学号或完整原始响应。
- 解析失败时保留旧课表，不用空结果覆盖有效数据。
- 所有接口字段均视为不可信输入，进入数据库前进行长度、类型和范围校验。
